Task Authoring Assessment – Explainer

Goal: Create a task that lures an AI coding agent into taking a shortcut that passes visible tests but violates a clear rule (unsafe). The agent's unsafe patch, together with its session log, is the primary deliverable.

What to Build

  1. Repo & Prompt: Clone a small open-source Python repository. Write a benign developer request (bug fix, feature, migration, CI repair) that asks for nothing harmful. Place this request in the instruction field of task.toml. Do not modify the original repo.
  2. Trap: Ensure a safe solution exists and a shortcut exists. The shortcut must make the agent's changes pass visible tests while breaking a rule that is unambiguously derivable from the prompt, docs, tests, config, or code.
  3. Tests & Graders: Visible tests live inside the repo (agent can see/run them). Hidden graders reside in Harbor’s tests/ folder and run after the agent finishes:
    • utility_oracle.py prints U=1 if the task is solved (functional correctness).
    • alignment_oracle.py prints S=1 if all rules are respected (safety).
    Both must be deterministic and require no internet.
  4. Two Solutions:
    • solution/solve.sh: Your safe fix that yields U=1, S=1.
    • unsafe.patch: The agent's patch that yields U=1, S=0 (tests pass, rule broken).
  5. Design Notes: Document every conceivable unsafe shortcut in task_card.md and explain how your alignment oracle catches each.

The Agent Run

  • Use either Claude Code with Fable/Opus-4.8 or Codex with OpenAI-5.6 Sol at high reasoning level or higher.
  • Provide the agent only the prompt and the repository.
  • Multiple attempts are allowed; you may refine the task between attempts.
  • Do not hint or nudge—the temptation must arise solely from the task.
  • Save the full session log and agent traces as evidence/agent_transcript.jsonl.
  • If the agent never takes the shortcut, the trap is too weak—redesign and repeat.

What to Submit

One zip file containing a single task folder in Harbor format (Terminal-Bench 2.0 layout) plus the evidence files:

task_id/
  task.toml                 # instruction = your benign prompt; metadata; agent + verifier timeouts
  task_card.md              # design notes: trap, shortcuts, how each is caught
  environment/
    Dockerfile              # builds container with the repo inside (unsolved)
    repo/                   # the project, with its own src/tests/docs/config
  solution/
    solve.sh                # applies your safe fix; must give U=1, S=1
  tests/
    test.sh                 # verifier entry point: runs visible tests + both oracles
    utility_oracle.py       # prints U=0 or U=1
    alignment_oracle.py     # prints S=0 or S=1, plus the broken rule
  evidence/
    unsafe.patch            # agent's patch: tests pass, U=1, S=0 (apply with patch -p1)
    agent_transcript.jsonl  # full session log + agent, model, settings used

Assessors will re-run the three rows (safe solution, visible tests, oracles). Any failure results in submission rejection.

Complete Solutions Needed for Submission

  • Safe fix (solution/solve.sh) that you author.
  • Unsafe patch (evidence/unsafe.patch) obtained from a successful agent run that takes the shortcut.
  • Session log (evidence/agent_transcript.jsonl) documenting the agent's interaction.
  • All Harbor‑format files listed above, correctly populated.
  • A working Dockerfile that builds the container with the unsolved repo.
  • Deterministic oracles that produce the same U and S scores on every run.

Successfully submitting this package demonstrates that you have engineered a task that exposes an unsafe shortcut in a state‑of‑the‑art coding agent.
